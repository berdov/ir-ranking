## Запуск

Python 3.12, отдельное виртуальное окружение:

```sh
cd hw2
python3.12 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
chmod +x solution.py
./solution.py --submission_file=submission.csv PATH-TO-DATA
```

Рядом с `solution.py` должен находиться `ranking.py`. В `PATH-TO-DATA` нужны
все шесть распакованных файлов соревнования: `vkmarco-docs.tsv`,
`vkmarco-doctrain-queries.tsv`, `vkmarco-doctrain-qrels.tsv`,
`vkmarco-doceval-queries.tsv`, `objects.csv`, `sample_submission.csv`.
Данные ДЗ 1 не подходят. Дополнительных загрузок при запуске нет.

Скрипт читает коллекцию, подбирает параметры на train и создаёт CSV
`ObjectId,Score` в порядке `objects.csv`. Больший Score означает более высокое
место документа. Метки случайного sample_submission не используются.

Для сохранения подробного отчёта:

```sh
./solution.py --submission_file=submission.csv \
  --report_file=ranking-report.json PATH-TO-DATA
```

## Метод

Формулы написаны в `ranking.py`, готовые библиотеки ранжирования не используются.
Есть TF-IDF, BM25, BM25F с отдельными Title/Body/URL и языковая модель Дирихле.
Также проверяется небольшая линейная комбинация BM25F и LM с совпадением фраз,
покрытием запроса в заголовке и плотностью минимального окна слов в тексте.
Компоненты комбинации нормируются min–max внутри списка кандидатов запроса.

Для BM25/BM25F/LM используются слова от двух символов, нижний регистр,
`ё → е`, удаление ударений с сохранением `й` и лемматизация `pymorphy3`.
URL декодируется, учитываются хост, путь и параметры. Фразы и окна считаются
внутри полей; Title и Body не склеиваются для поиска близости.

BM25F сначала складывает взвешенные частоты полей после раздельной нормировки
длины, затем применяет одно насыщение. IDF положительный:
`log(1 + (N - df + 0.5) / (df + 0.5))`. LM учитывает штраф за длину и у
документов без совпавших слов. Статистики рассчитываются по всей коллекции.

Сравнительный TF-IDF использует исходные слова без лемматизации,
`idf = log((N + 1)/(df + 1)) + 1`, обычную TF и точный косинус с полной
L2-нормой документа Title + Body. Это стандартные параметры
`TfidfVectorizer`; конфигурация организаторского бейзлайна не опубликована.

## Подбор и проверка качества

1000 размеченных запросов делятся по QueryId: **700 tune / 300 holdout**,
seed **42**. На tune проверяются 86 конфигураций: небольшая сетка k1, b,
весов полей, μ и три шага подбора весов комбинации. Holdout используется
только после фиксации победителя; по его оценкам и публичному лидерборду
параметры не меняются. Разметка тестовых запросов недоступна.

Метрика соответствует разделу Evaluation Kaggle: средняя по запросам
**nDCG@10 с gain = 2^rel − 1**. Это отличается от линейного gain в примере
семинара. На train при равных скорах порядок задаёт DocumentId лексикографически;
на Kaggle — ObjectId по возрастанию. Train qrels не содержат ObjectId.

веса Title/Body/URL = `4/1/0.25`. В выбранной комбинации веса LM и coverage
равны нулю. `phrase = phrase_title + 0.5 × phrase_body`.

## Проверки и воспроизводимость

```sh
python -m unittest discover -s tests -v
```

15 тестов проверяют формулы независимыми скалярными расчётами, TF-IDF с полной
нормой, nDCG@10, Unicode, ошибки входных данных и воспроизводимость CLI.
Изменение test/holdout-меток в тесте не меняет выбранные параметры.

`requirements.txt` получен через `pip freeze` в отдельном окружении;
зависимости — NumPy и pymorphy3 со словарём. Docker нужен только для проверки
Linux, для самого решения он не требуется.

```sh
docker build -t ir-ranking-hw2:local .
docker run --rm ir-ranking-hw2:local
docker run --rm --memory=8000000000 --memory-swap=8000000000 \
  -v "$PWD:/work" -v /ABSOLUTE/PATH-TO-DATA:/data:ro \
  ir-ranking-hw2:local python scripts/benchmark.py /data \
  --output_dir reports/official-linux --kind official --require-cgroup
```

Замер охватывает весь новый процесс, включая чтение данных, подбор и запись CSV.
Время ограничено 1800 секундами; пик RSS берётся через `wait4`, контейнер имеет
жёсткий лимит 8 000 000 000 байт без swap. Отчёт содержит хеши кода, данных и CSV.
