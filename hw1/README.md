## Установка и две обязательные команды

Поддерживается Python 3.12. В распакованном архиве:

```sh
python3.12 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
chmod +x solution.py
./solution.py --build_index --index_dir=index PATH-TO-DATA
./solution.py --submission_file=submission.csv --index_dir=index PATH-TO-DATA
```

В уже созданном проекте на Mac окружение находится в `../.venv`; достаточно
`source ../.venv/bin/activate` из каталога `hw1`.

В `PATH-TO-DATA` должны лежать четыре распакованных файла UTF-8:

| Файл | Поля |
| --- | --- |
| `vkmarco-docs.tsv` | Без заголовка: DocumentId, URL, Title, Body |
| `vkmarco-doceval-queries.tsv` | Без заголовка: QueryId, QueryText |
| `objects.csv` | Заголовок ObjectId,QueryId,DocumentId |
| `sample_submission.csv` | Заголовок ObjectId,Label |

TSV читается как текст с разделителями-табуляциями; кавычки считаются частью
текста, пустые Title/Body допустимы. Последнее поле может содержать табуляции.
В документах предполагается одна физическая строка на запись, как в заданном TSV.

Все внешние идентификаторы сохраняются строками: например, `001` и `1`
различаются. Выходной CSV имеет заголовок `ObjectId,Label` и порядок строк
`objects.csv`. С `sample_submission.csv` сверяется набор ObjectId; случайные
метки из примера не используются, его порядок может отличаться.

`requirements.txt` получен командой `python -m pip freeze` в отдельном чистом
окружении. Версии соответствуют зависимостям исходного шаблона курса.
Дополнительные корпуса NLTK скачивать не нужно: используется `RegexpTokenizer`.
SQLite, тесты и вспомогательные скрипты используют стандартную библиотеку Python.

## Как устроено решение

При построении каждому документу назначается внутренний номер от 0 до N−1.
Для каждого уникального слова из `preprocess(Title + ' ' + Body)` его номер
добавляется в список термина. Временные списки представлены массивами
`array('I')`, содержащими 32-битные целые. URL не участвует в индексации.

Списки уже отсортированы, поскольку документы обрабатываются по порядку.
На диск записываются разности соседних номеров, закодированные varint
с семью полезными битами в каждом байте. Разность меньше 128 занимает один
байт. Частоты, словарь и сжатые списки находятся в таблице `terms` файла
`index/index.sqlite3`, внешние номера — в `documents`. Полный индекс строится
для всего корпуса и не зависит от запросов или `objects.csv`.

При поиске словарь остаётся в SQLite. Загружается список только текущего
слова, из него формируется битовая маска документов. Для N=60 000 такая маска
занимает 7 500 байт. Маски слов запроса пересекаются побитовым AND, начиная
с наиболее редкого слова. Если слово отсутствует или пересечение пусто,
обработка запроса заканчивается досрочно.

Каждый запрос рассчитывается один раз. Его маска сохраняется во временной
SQLite-базе. Пары из `objects.csv` читаются построчно; в памяти остаются
не более примерно 1 МиБ масок и до 4 096 сопоставлений DocumentId. Кэш страниц
каждой из двух SQLite-баз ограничен 2 МиБ, `mmap` отключён. Временная база
и проверка ObjectId также находятся на диске и удаляются после завершения.
Для временных файлов используется системный каталог `TMPDIR` / `/tmp`.

Повтор слова в запросе ничего не меняет. Стемминг, лемматизация, стоп-слова
и замена `ё` на `е` не применяются. Пустой после токенизации запрос считается
И-запросом по пустому множеству и соответствует всем документам, включая пустые.
Это стандартная трактовка `all([]) == True`; отдельных указаний на этот
крайний случай в задании нет.

Ошибочные заголовки, повторяющиеся ID и ссылки на неизвестный запрос или
документ приводят к понятной ошибке. Индекс и сабмишн заменяются только после
успешного завершения: неудачный запуск сохраняет предыдущие файлы.

Построение использует память пропорционально числу пар «термин–документ»
и размеру словаря. Лимит 150 МБ в задании относится к **генерации**.
В генерации память не растёт пропорционально размеру всего индекса или
количеству пар: нужны ограниченные кэши и списки/маски текущего запроса.

## Как повторить замеры

Небольшую проверку можно выполнить с параметрами `--documents 1000 --queries 100
--objects 10000`. Для полного синтетического набора:

```sh
python scripts/make_synthetic_data.py reports/synthetic-local/data
python scripts/benchmark.py reports/synthetic-local/data \
  --output_dir reports/synthetic-local --kind synthetic
```

Генератор отказывается перезаписывать существующие входные файлы. Официальные
данные нужно хранить отдельно. Их запуск с заполнением `metrics.json`:

```sh
python scripts/benchmark.py PATH-TO-DATA \
  --output_dir reports/official --kind official
```

Результат окажется в `reports/official/submission.csv`. При повторном замере
следует обновить в README время `build.seconds`, `submission.seconds`, память
`submission.peak_rss_bytes` и размер `index_bytes` из `metrics.json`.
Флаг `--kind official` не подтверждает происхождение данных сам по себе,
но скрипт запрещает так маркировать свой набор с файлом `synthetic.json`.

Для Linux на Mac можно использовать Docker / OrbStack:

```sh
docker build -t ir-ranking-hw1:local .
docker run --rm -v "$PWD:/work" ir-ranking-hw1:local
docker run --rm -v "$PWD:/work" ir-ranking-hw1:local \
  python scripts/benchmark.py reports/synthetic-local/data \
  --output_dir reports/synthetic-linux --kind synthetic
docker run --rm --memory=100000000 --memory-swap=100000000 \
  -v "$PWD:/work" ir-ranking-hw1:local \
  ./solution.py --submission_file=reports/synthetic-linux/submission-limited.csv \
  --index_dir=reports/synthetic-linux/index reports/synthetic-local/data
```

Эта Docker-проверка ограничивает память процесса вместе с учтёнными ядром
страницами файлов. Построение запускается отдельно без этого ограничения.
Для сохранения JSON с RSS и событиями cgroup вместо прямого запуска решения:

```sh
docker run --rm --memory=100000000 --memory-swap=100000000 \
  -v "$PWD:/work" ir-ranking-hw1:local \
  python scripts/check_memory_limit.py reports/synthetic-local/data \
  --index_dir reports/synthetic-linux/index --output_dir reports/synthetic-linux-100mb
```

На обычном Linux независимый замер, указанный в задании:

```sh
/usr/bin/time -v ./solution.py --submission_file=submission.csv \
  --index_dir=index PATH-TO-DATA
```
