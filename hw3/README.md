Финальная модель: **ансамбль двух CatBoostRanker с YetiRank**.

| Проверка | nDCG@10 |
|---|---:|
| Подбор, 1000 запросов | 0.62473783 |
| Отложенная проверка, 1000 запросов | 0.61490662 |
| CatBoost YetiRank 200 на тех же отложенных запросах | 0.60857886 |
| Публичный лидерборд, финальный сабмишн | Ещё не отправлен |

Публичный бейзлайн соревнования: **0.61621**. Скор финального CSV на Kaggle
пока ожидает проверки. Локальная оценка считается на других запросах,
поэтому напрямую сравнивать её с лидербордом нельзя.

Лучшие параметры сохранены в `best_config.json`:

```text
loss_function=YetiRank, learning_rate=0.04, l2_leaf_reg=5, thread_count=4
features: 67 исходных + 67 рангов внутри запроса
модель 1: depth=6, iterations=697, random_seed=17, weight=0.5
модель 2: depth=8, iterations=792, random_seed=42, weight=0.5
предсказания каждой модели: z-score внутри запроса; затем среднее
```

Обучение и предсказание на Linux CPU: **обучение 240.56 с / 1332.86 MiB; предсказание 2.52 с / 584.11 MiB**.
Прогон: Python 3.12.16, Linux aarch64, 4 CPU-потока, жёсткий лимит 8 GB без swap.
[Отчёт полного прогона](reports/official-linux/metrics.json) содержит хеши кода, входов и CSV.

На отложенных запросах прирост составляет 0.00633 nDCG; парный bootstrap
даёт 95% интервал [0.00151, 0.01104]. Это оценка для выданных признаков
с учётом оговорки про `domain_prior` ниже. [Контрольный отчёт](reports/official/holdout.json).

## Запуск

Нужны Python 3.12 и отдельное окружение. На Debian/Ubuntu также нужен
`libgomp1` для LightGBM; Dockerfile устанавливает его автоматически.

```bash
cd hw3
python3.12 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt

./solution.py --train --model_file=model.bin PATH-TO-DATA
./solution.py --model_file=model.bin --submission_file=submission.csv PATH-TO-DATA
```

`requirements.txt` получен командой `pip freeze > requirements.txt` из
отдельного окружения ДЗ 3. В `PATH-TO-DATA` находятся официальные
`train.csv`, `test.csv`, `features.md`, `sample_submission.csv`.

Первая команда обучает модель на всех 7000 запросах train с фиксированными
параметрами и числом итераций. Подбор при этом не запускается.
Вторая загружает модель и читает только test. Результат содержит
`ObjectId,Score`; порядок и идентификаторы совпадают с `test.csv`.

## Данные и метод

Используются только 67 готовых признаков ДЗ 3. В train — 223044 пары для
7000 запросов, в test — 94633 пары для 3000 запросов. Запросы train/test
не пересекаются; пропусков и бесконечных значений нет. `QueryId` нужен
для группировки, `ObjectId` — для вывода: ни один из них не является
признаком модели. Тексты, исходные идентификаторы и внешние данные не используются.

Сравнивались CatBoost и LightGBM с исходными признаками и добавлением
рангов/minmax-нормировки внутри запроса. Преобразования рассчитываются
одинаково при обучении и предсказании; строки других запросов не влияют
на нормировку текущего запроса.

Разбиение с seed 42: **5000 запросов для обучения, 1000 для подбора,
1000 для отложенной проверки**. Все документы одного запроса находятся
в одной части. Сначала проверены 10 конфигураций, затем 11 уточняющих
вариантов и небольшая сетка смесей. Параметры, число итераций и веса
выбирались только по части для подбора; test не участвовал в выборе.
Seeds отдельных моделей и веса смеси записаны в `best_config.json`.

Для контрольной оценки выбранная конфигурация и бейзлайн обучаются на
6000 запросах. Финальное обучение использует все 7000 запросов.
Бейзлайн — CatBoostRanker с YetiRank, 200 итерациями и стандартными
параметрами модели; для воспроизводимости зафиксированы seed 0, CPU
и число потоков, отключена запись служебных файлов.

Готовый `domain_prior` уже содержит сглаженную статистику train-разметки.
Организаторы рассчитали её out-of-fold по запросам, но их folds неизвестны
и могут не совпадать с нашим разбиением. Поэтому локальную проверку нельзя
считать полностью независимой на уровне расчёта этой статистики.
Признак используется в выданном виде; домены не восстанавливаются.

## Метрика и проверки

27 тестов прошли на macOS и Linux. Два полных Linux-запуска дали побайтно
одинаковый CSV на всех 94 633 строках; второй запуск обучался 171.72 с
и использовал 1340.23 MiB. [Проверка воспроизводимости](reports/official/reproducibility.json). Проверены разбиение по запросам,
формула nDCG, отсутствие использования test при подборе, оба CLI-режима,
сохранение/загрузка моделей и точный порядок ObjectId.

nDCG@10 усредняется по запросам с равным весом: gain = `2**Label - 1`,
discount = `1/log2(position + 1)`, позиции начинаются с 1. На Kaggle
равные скоры разрешаются по возрастанию `ObjectId`. В train этого поля
нет, поэтому локальные равенства разрешаются исходным порядком строк.
Локально при нулевом IDCG результат равен 0; запросов со всеми нулевыми
оценками в выданном train нет. Формула сверена со скриншотом
Kaggle Evaluation и записана в [evaluation.json](reports/official/evaluation.json).

```bash
python -m unittest discover -s tests -v
python scripts/validate_submission.py PATH-TO-DATA submission.csv
python scripts/benchmark.py PATH-TO-DATA \
  --output_dir reports/official-linux --kind official
```

Benchmark запускает обе команды отдельными процессами и измеряет время
с импортами и максимальный RSS. Полный Linux-прогон дополнительно
выполняется в Docker с `--memory=8000000000 --memory-swap=8000000000`
и проверкой `--require-cgroup`. Лимит обучения по условию — 30 минут и 8 GB.

`model.bin` — архив с native-моделями и JSON-метаданными: схемой признаков,
параметрами, seeds и версиями библиотек. Данные, окружение, модели и CSV
сабмишнов исключены из Git. В репозитории остаются код, зафиксированные
зависимости, конфигурация и отчёты проверок.

После проверки публичного скора нужно записать его в этот README и
прикрепить ссылку на репозиторий в LMS.
